# ken-ai-plugin

> **Generated - do not edit the skills here by hand.** Everything in `plugins/ken-ai/` except `.codex-plugin/` is generated from the Kenso MCP skills, `mcp/src/ken_mcp/skills` in ken-backend, by `mcp/scripts/build_skill_packages.py`. Change a skill there and regenerate (see [Updating](#updating)).

Kenso skills for Claude Code, Cursor, Codex, GitHub Copilot, VS Code and any coding agent. The one plugin here, `ken-ai`, carries the skills Kenso's own agents run, for your Kenso workspace: build campaigns, handle replies, report results and keep sending healthy. It connects the Kenso MCP server (`https://mcp.ken.so/mcp`); sign in with your Kenso account when your agent asks.

No Kenso account yet? Create one at https://app.ken.so/get-started.

## Install

Claude Code:

```
/plugin marketplace add Ken-Technology/ken-ai-plugin
/plugin install ken-ai@ken-ai-plugin
```

Already installed? `/plugin marketplace update ken-ai-plugin` picks up the new version.

Cursor, Codex, GitHub Copilot CLI, VS Code, Grok Build and any other agent it finds on your machine, skills and Kenso MCP server together:

```
npx plugins add Ken-Technology/ken-ai-plugin
```

Skills only, into any agent that reads Agent Skills:

```
npx skills add Ken-Technology/ken-ai-plugin
```

This copies the skills but not the server: also add the Kenso MCP server, `https://mcp.ken.so/mcp`, to your agent ([steps for each agent](https://ken.so/mcp)).

In Claude Code, for example:

```
claude mcp add --transport http kenso https://mcp.ken.so/mcp
```

The server URL has not changed. Configs that already name the server `ken` keep working.

The skill list is in [plugins/ken-ai/README.md](plugins/ken-ai/README.md). Every skill asks before it sends, launches or changes a live campaign. MIT licensed, see [LICENSE](LICENSE).

## Updating

ken-backend publishes this repo; nobody copies by hand. Change a skill in ken-backend `mcp/src/ken_mcp/skills`, run `uv run python scripts/build_skill_packages.py` from its `mcp/` and commit the regenerated `mcp/directory/claude/` there. Once that reaches ken-backend `main`, its `ken-ai-plugin-sync.yml` workflow copies `mcp/directory/claude/` over `plugins/ken-ai/` (keeping `.codex-plugin/`), bumps the patch version in the three manifests, opens one PR here from `ci/ken-backend-sync` and merges it with a merge commit. A sync PR still open means that merge failed: read the run linked in its body, then merge it.

Run the sync by hand with `gh workflow run ken-ai-plugin-sync.yml -R Ken-Technology/ken-backend --ref main`. Without it:

1. In ken-backend, from `mcp/`: `uv run python scripts/build_skill_packages.py`. It writes the Claude package to `mcp/directory/claude/`.
2. Here, replace everything in `plugins/ken-ai/` except `.codex-plugin/` with the contents of `mcp/directory/claude/`.
3. Raise `version` in `plugins/ken-ai/.claude-plugin/plugin.json` past the published one, and set the same `version` in `.claude-plugin/marketplace.json` and `plugins/ken-ai/.codex-plugin/plugin.json`.
4. Check it: `claude plugin validate --strict --profile directory plugins/ken-ai` and `claude plugin validate .`, then open a PR.

`plugins/ken-ai/.codex-plugin/` is the one hand-kept part: the Codex manifest and its MCP config.

## Free skills without a Kenso account

The files-only cold email skills (no account, no MCP, MIT licensed) live in [Ken-Technology/cold-email-skills](https://github.com/Ken-Technology/cold-email-skills):

```bash
npx skills add Ken-Technology/cold-email-skills
```

That tree is generated by the same ken-backend script, and ken-backend publishes it the same way: its `cold-email-skills-sync.yml` workflow regenerates the tree whenever a skill changes on its `main`, and opens and merges one PR there. Run it by hand with `gh workflow run cold-email-skills-sync.yml -R Ken-Technology/ken-backend --ref main`. This repo no longer builds or publishes it (`free-distribution/README.md`).
